# 避碰框架审计与科研重构方案

> 历史审计：下文的“当前代码”指重构前v1.3.6。用户已批准实施，v1.4.0实际行为、公式、迁移及验证范围以 [REFACTOR_GUIDE.md](REFACTOR_GUIDE.md) 为准。

日期：2026-11-04。目标：科研仿真，规则可解释、PPO贡献可测、实验可复现。本文区分当前代码事实、最小复现、待验证假设和建议设计。方案尚待审阅，未修改算法行为，也未重新训练权重。文献与工业证据见 [研究笔记](COLLISION_AVOIDANCE_RESEARCH.md)。

## 1. 总体判断

当前项目是“规则筛选高层意图 + 采样式预测规划 + 简化船舶动力学”的研究原型。PPO的独立决策空间很小；界面上的PPO动作不能直接代表实际操纵。标准追踪表也明确承认DCRC/DCQS、SDA数据和测试场景尚不完整，不能将“依据标准设计”写成“已验证符合标准”。

已读取项目所附 `ccs标准.pdf`，实际封面为GB/T 46851—2025。**附录A、B、C、D均为资料性**：A是“一种右舷交叉会遇局面下”的风险量化方法，B是安全会遇距离数据库示例，D是测试场景示例。因此，不复现A的DCRC/DCQS算法本身不等于违反规范性要求；若项目声称采用A算法，就必须准确复现或明确标注替代方案。重构应优先逐项追踪正文功能/性能/测试要求，而不是把资料性示例当作唯一合法实现。正文7.3.2要求避让最小距离不小于设定SDA，SDA设定可参照附录B；7.3.1要求全目标分析、不能引入新碰撞危险、驶过让清及稳定决策。

主要调用链：`train_ppo.SamplingPolicy → engine.step(action_override) → 规则改写/策略保持 → planner.plan → dynamics.step`。推理还包含20秒高层决策保持。PPO并不直接输出舵角或推进指令。

## 2. 为什么只有五种，为什么没有加速追越

代码中存在两套恰好都是五项的枚举：

| 维度 | 当前枚举 | 位置 |
|---|---|---|
| 会遇 | 对遇、右舷交叉、左舷交叉、本船追越、本船被追越 | `usv_sim/colregs.py:classify_encounter` |
| PPO动作 | 保持、右转、左转、减速、右转并减速 | `usv_sim/ppo_agent.py:ACTION_INTENTS` |

“加速追越”是会遇关系与操纵的组合，适合显示成“本船追越 / 让路 / 右舷通过 / 加速”，不应混成另一个互斥会遇状态。目标船位于本船右侧，也不等于本船应在目标右侧通过。

标准附录C进一步给出左/右舷对遇、右舷交叉/右正横/左舷交叉/左正横、左/右舷追越及被追越的测试细分。当前五类合并了这些细分，不能认为已经覆盖该示例分类；可以把几何子类与责任主类分别保留。标准第1章适用范围是开阔水域，窄通道/内河扩展实验需另行定义ODD及规则依据，不能直接套用本标准的适用性结论。

缺少加速能力却是事实：PPO没有加速动作；`_speed_candidates`只包含当前速度、巡航速度及几个减速值。本船低于巡航速度时可以恢复巡航，但当前等于巡航7 m/s时，追越候选为 `[7, 6.4, 5.8, 5, 2]`，不会主动搜索8或9 m/s。

追越还存在接口退化：掩码只允许动作0，而引擎强制将其变成 `overtake`，通过侧与速度均由规划器决定。不能据此声称PPO学到了追越策略。

分类器是启发式，不完整：正前方同航同速的目标因TCPA=0而无法识别追越，最终落入左舷交叉；落在“正在追越”之外的平行/远离场景也会被强制归入交叉。这不意味着同速尾随一定应归追越，而是需要独立的“尾随/无活跃会遇/不确定”状态，不能靠交叉兜底。Rule13的疑义、责任持续和驶过让清需独立表达。

## 3. 当前MPC究竟做了什么

### 3.1 预测模型

状态为 `x=(X,Y,ψ,u,v,r,δ,n)`，航向0为北、正方向顺时针。`dynamics.py`采用限幅的一阶舵机、Nomoto-like艏摇、纵向速度滞后及简化横荡，非经过试航辨识的MMG。忽略限幅与环境项时，其核心可写为：

\[
\dot\delta=(\delta_c-\delta)/T_\delta,\quad
\dot r=(K\delta\max(0.25,u/7)-r)/T_r,\quad
\dot u=(u_c-u)/T_u,
\]
\[
\dot\psi=r,\quad
\dot X=u\sin\psi+v\cos\psi+c_X,\quad
\dot Y=u\cos\psi-v\sin\psi+c_Y.
\]

实际代码对舵角、舵速、艏摇率、加减速度和航速限幅，并离散积分；横荡通过 `v_target=-0.12ur` 的滞后更新。以上是现有仿真模型，不是标准规定的操纵方程。

### 3.2 优化变量与滚动执行

每轮枚举最终航向/速度设定值 `(ψ_c,u_c)`；向该航向限速爬升，经航向控制器变为舵指令，模拟未来约1000～1500秒，最多120个预测步。选好后只执行第一个受限指令，下一轮重算。这是有限候选的采样式滚动预测控制；没有求解一般的时变控制序列 `u_0,...,u_{N-1}`，也不等同标准动力学窗口DWA。

以 `m=distance-SDA_pref` 为动态船舶裕度，`SDA_pref=(λ_1+0.274)SDA` 为当前代码公式；SDA内已乘船型因子，能见度低于1海里时 `λ_1=2`，否则为1。标准附录A式(A.3)写为 `(λ_1λ_2+λ_M)SDA`，且λ1还涉及夜间。当前将船型因子预先乘入SDA，会使操纵富余项也乘船型因子；应先澄清基准SDA、调整后SDA及富余项的变量契约，不能仅凭代码注释认定等价或再盲目乘一次λ2。静态障碍裕度为中心至多边形距离减去 `0.5L+100m`。

若某预测时刻裕度为负，记该候选unsafe；累计违反量D。动态项增加 `1+(-m/SDA)^2`，静态项增加 `2+(|m|/100)^2`，初始时刻动态项分母另用SDA_pref。

当前标量代价为：

\[
\begin{aligned}
J={}&\mathbf1_{unsafe}(100000+5000D)
+8\overline C_{risk}+4\overline C_{obs}
+0.40\overline e_\perp/1000+0.002e_{\perp,N}\\
&+0.035|e_{\psi,N}|_{deg}+0.045|\Delta\psi|_{deg}
+0.020\sqrt{\overline{\delta_{deg}^2}}
+0.025|\psi_c-\psi_{c,prev}|_{deg}\\
&+0.08|u_c-u|+10000\mathbf1_{opposite}
-0.0004\max(0,\Delta s_N).
\end{aligned}
\]

其中 `C_risk=max(0,1.15-distance/SDA_pref)^2`；静态项是 `max(0,(500-m_obs)/500)^2`。**实际选择还先比较字典序 `(unsafe,D,opposite,J)`**，不能只解释这个加权和。无完全安全候选时仍会返回并执行违反量最小的候选。

问题：长时域预测依赖理想目标行为；约10秒的离散采样可能漏掉采样点间穿越；初始已进入偏好安全带会使全部候选unsafe。偏好间距违反、实体碰撞与必须采取应急不能用同一个布尔值表达。这里的safe只表示有限采样/有限预测模型内通过，不能证明连续时间安全或递归可行性。

## 4. 当前PPO奖励、回报和更新公式

`train_ppo.step_reward`中，令 `Δs` 为本步沿航线进展、`e⊥` 为横向距离、`δ,r` 为弧度量；只对TCPA>0目标取 `m=min(DCPA-SDA)`、`q=min(DCPA/SDA)`。代码对应：

\[
\begin{aligned}
r_t^{raw}={}&0.08\frac{\Delta s}{\max(u_{nom}\Delta t,1)}
-0.10\min(3,e_\perp/1500)-0.06|\delta_t|\\
&-0.10|\delta_t-\delta_{t-1}|-0.04|r_t|
-0.90\max(0,-m/1000)-0.18\max(0,1.20-q)\\
&-1.50\mathbf1_{plan\ unsafe}
-0.75\mathbf1_{rule\ action\ mismatch}
-100\mathbf1_{new\ collision}
+3\mathbf1_{route\_returned},\\
r_t={}&\operatorname{clip}(r_t^{raw},-25,5).
\end{aligned}
\]

无TCPA>0目标时不加m、q两项。规则不匹配是：步进后快照中最高风险让路目标属于对遇/右舷交叉，且 `engine.last_action` 不是1或4。

回报并非简单本步奖励。代码用GAE：

\[
\delta_t^{TD}=r_t+0.99(1-d_t)V(s_{t+1})-V(s_t),\quad
\hat A_t=\delta_t^{TD}+0.99\cdot0.95(1-d_t)\hat A_{t+1},\quad
\hat R_t=\hat A_t+V(s_t).
\]

碰撞、到达、接管视为terminal，不bootstrap；时间截断用末状态价值bootstrap。优势再标准化。

\[
\rho_t=\exp(\log\pi_\theta^{M_t}(a_t|s_t)-\log\pi_{old}^{M_t}(a_t|s_t)),
\]
\[
L=-E[\min(\rho_t\hat A_t,\operatorname{clip}(\rho_t,0.8,1.2)\hat A_t)]
+\tfrac12E[(\hat R_t-V_\theta(s_t))^2]-0.01E[H(\pi_\theta^{M_t})].
\]

Adam学习率3e-4，默认4轮PPO更新，batch128、梯度范数上限0.5。网络为42维输入、两层128 Tanh、5维actor和1维critic。默认8轮规则伪标签交叉熵预热，不是专家轨迹模仿。

确定的问题：

1. `route_returned`是持久标志，之后每步加3而非仅事件发生时加一次；其量级远大于每步约0.08的进展奖励，可能鼓励拖延。是否已在权重中出现需轨迹验证。
2. 碰撞-100经整体裁剪通常降至-25，不能把-100当有效终端惩罚。
3. 风险项只看TCPA>0，忽略CPA后仍近距离、相对静止的危险；规划器用SDA_pref，奖励用SDA，安全口径不一。
4. 舵角、舵变化、艏摇均为弧度，相关项通常较小；各项需分量日志，不能只看总reward。
5. 规则惩罚检查步进后的责任状态，与采样时情景可能不同；策略保持期间动作0代表保持避让，却仍可能因不是1/4被扣分。
6. 训练dt=10秒且每步采样；常用评估dt=2秒且高层20秒采样。相同γ按步折扣对应不同物理时长，控制与策略节拍也改变，属于环境分布差异。

## 5. 掩码到底根据什么设置

`engine.action_mask`当前按以下优先级返回：

| 条件 | 允许动作 |
|---|---|
| 无目标 | 仅0 |
| 已有避让策略、非紧迫 | 仅0，保持原策略 |
| 已有避让策略、紧迫 | 全部五项 |
| 未避让，最高风险让路目标为对遇/右舷交叉 | 仅1和4 |
| 未避让，最高风险让路目标为本船追越 | 仅0，后续强制变成overtake |
| 其余紧迫情况 | 全部五项 |
| 其余情况 | 仅0 |

让路目标筛选为 `own_give_way && risk_score>=0.12 && TCPA>0`。它没有预测具体动作是否撞到其他船/岸，没有统一求所有目标规则约束交集；`giveway_targets`里只取一个最高风险目标来确定掩码。且未避让时对遇/交叉分支先于紧迫分支，不能笼统说“紧迫一律开放全部”。

掩码策略为 `π^M(a|s)=M(s,a)exp(z_a)/Σ_b M(s,b)exp(z_b)`。现有训练保存每步mask，更新时复用这一mask，这一点是正确的。不应把PPO样本动作直接换成末端执行动作，再沿用原log-prob。

单一允许动作时概率恒为1，熵和actor策略梯度均为0；critic仍可学习，共享网络仍可能被critic更新。PPO没有整体失效，但这一段没有动作选择可学。

## 6. 硬规则与两重保险

当前有至少三处约束：mask、引擎重写意图及策略保持、规划器方向惩罚和安全字典序。因此并非只有两层。

- 对遇/右舷交叉将maintain/port改为starboard，将slow改为starboard_slow；追越无论原动作如何均改成overtake。
- 普通避让持续保持初始策略，仅部分紧迫情况可升级；参与目标集合主要在启动时建立，后续新目标需额外处理。
- 规划器即使意图starboard仍保留部分左转候选，以opposite标志和代价排序；不存在严格形式化的“永远禁止左转”。

Rule14对遇的右转要求不能机械扩展成Rule15交叉必须右转；后者重点是让清及在情况许可时避免横越他船前方。Rule17存在“可采取行动”与“必须采取行动”的不同阶段，当前仅以紧迫标志切换过粗。受限能见度Rule19、特殊船舶Rule18和狭水道/分道通航适用性要么支持，要么明确排除在实验ODD外。

两重保险可以保留。**问题是干预是否有统一语义，以及是否把全部可学选择提前消掉。** 对确定性安全屏障构成的环境，PPO仍可合法优化原始提议动作产生的闭环回报；执行映射本身不自动导致PPO数学错误。但大量动作同义、隐藏的策略锁存状态、训练推理节拍差异会使学习作用很弱、观测不充分和解释失真。

## 7. 其他重要缺口与证据等级

| 优先级 | 问题 | 证据 |
|---|---|---|
| P0 | TCPA<=0直接无危险；近距离同速船也会无危险 | `risk.py`；最小复现：相隔1m同航同速，TCPA=0，risk_score=0 |
| P0 | 目标速度变化预测与真实更新不同 | `TargetShip.update`每次最多改0.04m/s，预测每秒最多0.04m/s；10秒复现真实Y=50.4、预测Y=53.0 |
| P0 | 目标预测知道脚本未来转向/变速时间 | `predict_position`读取脚本；默认不应当作真实传感器可获得的未来意图，会高估算法 |
| P0 | 标准附录完整性不足、来源和阈值未形成版本化追踪 | `STANDARD_TRACEABILITY.md`、`sda.py`自己声明部分表和尺度估计；需逐公式/表/测试核对原文 |
| P1 | PPO观测无静态障碍、环境/ODD、当前策略、锁存阶段/已选侧/上次控制；只编码3艘目标 | `build_observation`；同一42维观测可对应不同mask与执行映射 |

| P1 | 多船目标的规则冲突没有统一可行性处理 | 高层选一个让路主目标；下层虽看全部船舶距离，仍不等于全目标规则验证 |

| P1 | 动力学积分与规划步长不同，采样间碰撞未校核 | `dynamics.step`、规划dt与控制dt；幅度/性能影响待收敛试验 |
| P1 | 只使用route[0]，并非通用多航点跟踪 | `engine.__init__` |
| P2 | 船舶碰撞用简化圆阈值，静态接触用另一半船长圆；碰撞计数是接触步数 | `engine.step`；需要区分事件数、接触时长和船体几何 |
| P2 | 返回航线使用持久历史标记，终点判定可接受历史回归且当前偏航 | `passed_route_end && (recovered_now || route_returned)` |
| P2 | engine多次assess修改会遇记忆，释放条件按调用次数而非物理时间 | 初始化、步前、步后均可能调用；应改成显式时间驱动 |

“已定位代码缺口”不等于“所有场景都表现失败”，表中性能与学习后果需实验量化。

## 8. 三种重构路线

| 路线 | 收益 | 代价/限制 |
|---|---|---|
| A 局部修补五动作框架 | 变动最小，可快速修复奖励、预测和时序 | 追越及避让期间仍缺PPO决策空间，难支撑学习贡献论文 |
| **B 统一规则+候选轨迹+PPO选择（推荐）** | 保留动力学/界面，规则与安全同源；PPO可在可行轨迹间比较效率，可做严格消融 | 更改动作/观测契约，现有权重需要重训 |
| C 连续动作PPO+鲁棒NMPC/CBF过滤 | 控制空间更丰富，可研究鲁棒安全学习 | 船舶模型、求解器与安全证明要求高，当前原型直接迁移风险大 |

## 9. 推荐B：职责与数据契约

数据流：`观测及不确定性 → 会遇/责任/阶段管理 → 统一规则约束 → 可达候选轨迹及特征 → 可行性mask → PPO或确定性基线选候选 → 末端独立校核 → 执行 → 分量日志`。

### 9.1 独立语义

- Encounter：对遇、交叉、追越、尾随/无活跃会遇、不确定；几何判断和责任记忆分开。
- Responsibility：让路、直航、共同避让、特殊/未知。
- Phase：监测、应让路、直航可干预、必须应急、驶过让清、回归；用时间和置信度设置滞回，保留Rule13责任至让清。
- Maneuver：航向改变量、速度设定、左/右通过、保持时间；UI同时显示原始提议、实际执行及原因。

用一个 `RuleContext` 输出适用条款、每目标约束、偏好、原因码和适用ODD。禁止训练、引擎和规划器各复制一份规则逻辑。多个目标逐一校核，冲突显式记录。

### 9.2 候选轨迹与PPO

采用固定上限候选槽位，每槽含 `candidate_id, course_profile, speed_profile, predicted_path, features, feasible, reason_codes`；不生成的槽位mask=0。候选包含保持、左右明显转向、纯减速、转向加减速、具备船型模型支持的停车等组合。加速候选 `u_c∈{u,u-Δu,u+Δu,u_cruise,u_max}` 经执行器、航道、安全速度及全目标校核筛选；追越允许两侧但不允许以加速破坏让清责任。

先为每候选做预测，PPO在可行候选之间选择，因此动作效果不再被下层重新覆盖。保持已选通过侧及承诺时间是可见状态与软切换代价，不是从避让开始直到结束仅剩动作0；安全需要时解除承诺。

建议候选共享评分网络，输入本船/航线/阶段与各候选特征，输出每槽logit；目标集合用带存在mask的共享编码或集合聚合，避免固定前三艘及风险排序身份跳变。先实现最小可测版本，再考虑注意力网络。

只有决策时刻保存PPO transition，期间执行低层控制；训练、推理统一积分dt、控制dt、策略周期。变时长决策用 `γ_t=exp(-βΔt_t)` 与对应时间尺度GAE；初版固定策略周期以降低复杂度。

### 9.3 双层保险的明确职责

第一层mask：过滤当前状态和预测假设下确定不可行的轨迹。硬约束包括执行器极限、船体/障碍防碰、明确适用的规则禁限；偏好SDA、效率和舒适度分开。

第二层末端监控：用最新状态、短周期和扫掠几何复查要执行的首段，捕获新目标、状态跳变与计算超时。它共享规则规格但具有独立检查职责；共享模型仍可能共因失效，不能宣称独立安全冗余已被证明。

全部候选不可行时进入明确的最小风险/接管状态，记录不可行原因、违反级别和选用恢复动作，禁止把它报告为safe。停车不是所有场景的默认安全解；是否能停车由船型模型支持。研究仿真中的接管需定义可运行的后备策略与失败记账。

若监控改写执行，保存 `proposed_candidate, executed_control, intervention_reason`。PPO更新仍使用采样的提议动作及其log-prob，以实际闭环回报学习；不把被替换动作冒充采样动作。干预样本可做额外辅助监督，但要与PPO损失分开。

### 9.4 奖励重设

采用有物理尺度的分量，配置文件显式给权重，初始权重只能是待校准假设：

\[
r_t=w_p\Delta s/s_0-w_t\Delta t/t_0-w_e\int e_\perp^2dt/E_0
-w_u\int(\dot\delta^2+\kappa\dot u^2)dt/U_0
-w_d C_{domain}-w_i\mathbf1_{intervention}
+R_g\mathbf1_{goal\ event}-R_c\mathbf1_{collision\ event}.
\]

安全由约束和监控承担，罚分用于学习收益；不能靠加大碰撞负奖励当安全证明。回归奖励只在事件沿触发一次，或用 `γΦ(s_next)-Φ(s)` 做明确定义的势函数塑形。首版去掉整体硬裁剪，使用可追踪的尺度归一化并监控异常值；若需要裁剪，要报告裁剪比例及有效终端惩罚。先不承诺某组系数最优。

阶段3：引入候选选择PPO，统一训练推理执行链，重训并做以下消融。旧模型标记legacy，禁止默默加载进新动作空间。

指标分开报告：实体碰撞事件与持续时间、最小船体间距、领域侵入深度/时长、条款及阶段违规、到达/超时、航程/时间/推进能耗代理、动作反复、不可行率、规划延迟p50/p95/p99、超时率、有效动作数、mask单动作比例、监控干预率。规划截止时间由固定控制周期配置，不只报告平均运行时间。

判断PPO有效必须满足：在同安全约束与测试集下，相比确定性基线在预先指定的效率指标有稳定改善；同时安全/规则指标不退化。若候选几乎始终只剩一个或收益不显著，结论应是该ODD下PPO没有证明额外价值，允许保留为可选模块。
