# 用户上传案例数据审计（v1.2.0）

## 1. 文件数量与记录结构

| 案例组 | CSV 文件数 | 目标船记录数 |
|---|---:|---:|
| 1T | 138 | 138 |
| 2T | 99 | 198 |
| 3T | 31 | 93 |
| **合计** | **268** | **429** |

数据目录另包含原案例包中的预览图片。每个 CSV 文件表示一个初始会遇场景；每行代表一艘目标船，而不是一个连续时间采样点。

## 2. 已使用字段

加载器读取并转换本船/目标船经纬度、SOG、COG、距离相关字段，以及 `meeting_situation`、`stage`、`DCPA(NM)` 和 `TCPA(min)`。经纬度按本船初始位置转换为本地东-北平面坐标；节换算为 m/s；初始本船 COG 用作初始航向。

全数据集 `stage` 标签统计：

- `碰撞危险`：386 条目标船记录
- `没有危险`：43 条目标船记录

数据中包含 17 种不同的 `meeting_situation` 标签。

## 3. 重要缺失字段

本次审计发现以下字段在 429 条目标船记录中均为空：

| 字段 | 空值记录数 |
|---|---:|
| `visibility` | 429 |
| `ownship_behavior` | 429 |
| `target_behavior` | 429 |

因此，不能从当前 CSV 得到每艘船的真实尺度、船型、舵机参数、能见度，以及目标船在未来时刻的实际转向/变速轨迹。工程中按以下方式处理：

1. 本船长度和每艘目标船长度由界面设定；训练时在 50～500 m 的离散长度选项中随机化。这些长度不是 CSV 标签。
2. 目标船未来运动默认采用恒速恒向模型。只有在另外配置 JSON 行为脚本时，才会执行延迟转向或变速。
3. 能见度使用环境配置默认值，不能声称是原始案例实测能见度。
4. `meeting_situation` 源标签与运行时几何分类分开保留，界面风险表同时显示“案例标签”和“程序识别”，供人工核验；不会为了强行一致而覆盖原始数据或几何结果。

## 4. 训练中如何使用这些案例

### Rule-policy warm start

每个 CSV 场景的初始状态被读取一次；`stage` 用作目标船风险标签的参考，生成规则策略伪标签。该数据不是人工专家操船轨迹，因此 warm start 不能称为模仿专家演示。

### PPO simulation rollouts

PPO 回合从这 268 个初始场景中抽样。之后的船舶运动由仿真器生成：本船由简化 3-DOF/Nomoto-like 操纵模型推进，目标船默认恒速恒向。回合长度根据 CSV 中最大正 TCPA 自动延长，并设置 600 s 的 CPA 后观察时间，受最大回合步数上限约束。

因此，本数据适合做**场景初始化训练与规则/策略仿真评估**，不等同于使用真实连续轨迹监督训练。

## 5. TCPA 与回合时长

数据集中最大正 TCPA 为 183.58 min。v1.2.0 将该值用于生成足够长的默认航线和 episode 上限计算，避免长 TCPA 场景在预计会遇发生前就因航线终点而提前结束。

## 6. 适用边界

案例数据只描述初始会遇状态和若干计算/标签字段。若要训练目标船协同行为、目标船避让策略或对真实操船行为进行监督，需要补充逐时刻 AIS/雷达轨迹、目标船行为标注、船长/船宽/船型和环境观测数据。
